--------------------------------------------------------------------------------
1. SHULKER BOX COMPOSITE : TREATING SINGLE ITEMS AND NESTED BOXES UNIFORMLY
--------------------------------------------------------------------------------
Shulker Box Composite : Treating single items and nested boxes uniformly

--------------------------------------------------------------------------------
2. MINECRAFT METAPHOR CREATIVE EXPLANATION
--------------------------------------------------------------------------------
In Minecraft, a Shulker Box can store individual items like Diamonds or even nested 
smaller Shulker Boxes inside it. The Composite pattern allows both individual items and 
container boxes to implement the exact same item interface, letting you inspect or manage 
a single item or an entire recursive nested container hierarchy uniformly without checking 
types.

--------------------------------------------------------------------------------
3. DESIGN PATTERN TITLE & SUMMARY
--------------------------------------------------------------------------------
Composite Pattern : Composes objects into tree structures to represent part-whole hierarchies. 
Composite lets clients treat individual objects and compositions of objects uniformly.

--------------------------------------------------------------------------------
4. DESIGN PATTERN CORE IDEA
--------------------------------------------------------------------------------
- Component: Declares the interface for objects in the composition and implements default behavior.
- Leaf: Represents leaf objects in the composition with no children (primitive items).
- Composite: Defines behavior for components having children and stores child components.
- Client: Manipulates objects in the composition through the Component interface.

--------------------------------------------------------------------------------
5. NORMAL APPROACH VS. DESIGN PATTERN APPROACH
--------------------------------------------------------------------------------
- Normal Approach: Writing messy conditional type-checking code (e.g., `if (item instanceof ShulkerBox)`) 
  to recursively handle nested inventories, leading to fragile and complex logic.
- Design Pattern Approach: Utilizing a unified component interface so clients treat leaves and 
  composites identically, enabling seamless recursive traversal.

--------------------------------------------------------------------------------
6. FILE LIST & ORDER
--------------------------------------------------------------------------------
1. ItemComponent.java - Component interface defining standard display and count methods.
2. SingleItem.java - Leaf class representing individual non-container items.
3. ShulkerBox.java - Composite class representing a container box holding other item components.
4. TestComposite.java - Client class demonstrating recursive inspection of nested shulker boxes.

7. SIMPLE INTERACTION FLOW
