--------------------------------------------------------------------------------
1. CRAFTING RECIPE BOOK FACADE : SIMPLIFYING COMPLEX SUBSYSTEMS INTO ONE CLICK
--------------------------------------------------------------------------------
Crafting Recipe Book Facade : Simplifying complex crafting subsystems into one click

--------------------------------------------------------------------------------
2. MINECRAFT METAPHOR CREATIVE EXPLANATION
--------------------------------------------------------------------------------
In Minecraft, crafting a complex item like an Enchantment Table requires checking your 
inventory for diamonds, obsidian, and books, consuming them in exact grid positions, 
playing a placement sound, and spawning the result. Instead of forcing the player to 
manually orchestrate all these separate subsystems, the Recipe Book Facade provides a 
single unified button that handles the entire complex workflow behind the scenes.

--------------------------------------------------------------------------------
3. DESIGN PATTERN TITLE & SUMMARY
--------------------------------------------------------------------------------
Facade Pattern : Provides a unified interface to a set of interfaces in a subsystem, 
making the subsystem easier to use by defining a higher-level interface.

--------------------------------------------------------------------------------
4. DESIGN PATTERN CORE IDEA
--------------------------------------------------------------------------------
- Facade: Knows which subsystem classes are responsible for a request and delegates 
  client requests to appropriate subsystem objects.
- Subsystem Classes: Implement subsystem functionality, handle work assigned by the 
  Facade object, and have no knowledge of the facade.
- Client: Interacts with the subsystem through the simple Facade interface rather 
  than dealing with multiple complex classes directly.

--------------------------------------------------------------------------------
5. NORMAL APPROACH VS. DESIGN PATTERN APPROACH
--------------------------------------------------------------------------------
- Normal Approach: Client code directly instantiates and coordinates multiple subsystem 
  classes, resulting in high coupling and messy procedural code.
- Design Pattern Approach: Wrapping subsystem complexity behind a clean facade interface, 
  simplifying client usage and decoupling client code from internal subsystem changes.

--------------------------------------------------------------------------------
6. FILE LIST & ORDER
--------------------------------------------------------------------------------
1. PlayerInventory.java - Subsystem class managing resource items and inventory checks.
2. ItemRegistry.java - Subsystem class verifying recipes and material availability.
3. SoundManager.java - Subsystem class handling crafting and click audio cues.
4. CraftingRecipeBookFacade.java - Facade class unifying the crafting subsystems.
5. TestFacade.java - Client class demonstrating quick-crafting via the recipe book.

--------------------------------------------------------------------------------
7. SIMPLE INTERACTION FLOW
--------------------------------------------------------------------------------
Client -> CraftingRecipeBookFacade -> [PlayerInventory, ItemRegistry, SoundManager]

--------------------------------------------------------------------------------
8. INTERVIEW TIP
--------------------------------------------------------------------------------
Explain that the Facade pattern is like the Minecraft Recipe Book button. Instead of 
manually checking your inventory, verifying recipes, and triggering sounds separately, 
you click one single button that orchestrates all those complex subsystems behind 
the scenes.
