--------------------------------------------------------------------------------
1. MINECRAFT REDSTONE OBSERVER BLOCK : EVENT-DRIVEN NOTIFICATION
--------------------------------------------------------------------------------
Minecraft Redstone Observer Block : Event-driven notification

--------------------------------------------------------------------------------
2. MINECRAFT METAPHOR CREATIVE EXPLANATION
--------------------------------------------------------------------------------
In single-player Minecraft, instead of constantly checking if your wheat crops have 
finished growing by walking up to them every few minutes (polling), you place a Redstone 
Observer Block facing the crop. The observer quietly monitors block state changes. The 
exact millisecond the wheat reaches maturity, the observer fires a redstone pulse automatically, 
instantly triggering all connected devices—like a Redstone Lamp lighting up or a Piston 
Harvester breaking the crop. The Observer pattern establishes a one-to-many subscription 
model where state changes in a subject automatically notify all registered observers.

--------------------------------------------------------------------------------
3. DESIGN PATTERN TITLE & SUMMARY
--------------------------------------------------------------------------------
Observer Pattern : Defines a one-to-many dependency between objects so that when one object 
changes state, all its dependents are notified and updated automatically.

--------------------------------------------------------------------------------
4. DESIGN PATTERN CORE IDEA
--------------------------------------------------------------------------------
- Subject (`CropBlock`): Maintains a list of observers and notifies them of state changes.
- Observer Interface (`RedstoneObserver`): Declares the update interface for receiving notifications.
- Concrete Observers (`RedstoneLamp`, `PistonHarvester`): Implement actions to take when notified.

--------------------------------------------------------------------------------
5. NORMAL APPROACH VS. DESIGN PATTERN APPROACH
--------------------------------------------------------------------------------
- Normal Approach: Active polling (checking crop status in a continuous loop), 
  leading to wasted CPU cycles and tightly coupled, unmaintainable code.
- Design Pattern Approach: Event-driven notification, allowing components to subscribe 
  and react asynchronously only when state changes occur.

--------------------------------------------------------------------------------
6. FILE LIST & ORDER
--------------------------------------------------------------------------------
1. RedstoneObserver.java - Observer interface for listening to block state updates.
2. CropBlock.java - Subject class representing the monitored wheat crop.
3. RedstoneLamp.java - Concrete observer representing a lamp that lights up upon maturity.
4. PistonHarvester.java - Concrete observer representing an automatic piston harvesting device.
5. TestObserver.java - Client class demonstrating subscription management and event propagation.

--------------------------------------------------------------------------------
7. SIMPLE INTERACTION FLOW
--------------------------------------------------------------------------------
CropBlock.grow() -> State changes -> notifyObservers() -> RedstoneObserver.update() -> Connected devices react

--------------------------------------------------------------------------------
8. INTERVIEW TIP
--------------------------------------------------------------------------------
Explain that the Observer pattern is foundational for event-driven architectures and GUI frameworks. 
Emphasize how it decouples the event source from its listeners, preventing tight coupling and active polling.
